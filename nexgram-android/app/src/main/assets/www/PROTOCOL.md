# NGP — NexGram Protocol v1

Свой прикладной протокол комнаты. Не MTProto и не Signal.
Транспорт: WebSocket, путь `/ws`, текст UTF-8, один JSON-кадр = одно сообщение.

## Кадр

```json
{
  "p": "NGP",
  "v": 1,
  "t": "HELLO",
  "id": "8-символьный hex",
  "ts": 1779280000000,
  "body": {}
}
```

| Поле | Смысл |
|---|---|
| `p` | Всегда `NGP`. Иное — отбросить. |
| `v` | Версия. Сейчас только `1`. |
| `t` | Тип кадра. |
| `id` | Идентификатор кадра, для ACK и ошибок. |
| `ts` | Время отправителя, мс. |
| `body` | Полезная нагрузка типа. |

Неизвестные поля игнорировать (совместимость вперёд).
Кадр длиннее 24 КБ — отбросить.

## Типы

### Сессия

`HELLO` клиент → сервер  
`body`: `{ "client": "nexgram-web/0.3", "features": ["aes-gcm", "history"] }`

`WELCOME` сервер → клиент  
`body`: `{ "server": "nexgram-relay/0.3", "sid": "...", "features": ["aes-gcm", "history", "commit"] }`

Без `HELLO` остальные кадры не принимаются (`ERROR` код `NO_HELLO`).

### Комната

Пароль по проводу **не едет**. Клиент считает `commit`:

```
commit = hex( SHA-256( "NGP1-commit:" || room || ":" || password ) )
```

Ключ шифрования другой:

```
key = PBKDF2-HMAC-SHA256(password, salt="NGP1-aes:"||room, 120000, 256 bit)
```

`JOIN` клиент → сервер  
`body`: `{ "room": "team-altai", "nick": "Николай", "commit": "64 hex" }`

Сервер:

- если комната пустая — запоминает `commit`;
- если нет — сравнивает с первым. Не совпал → `ERROR` `BAD_COMMIT`;
- пароль не хранит.

`JOINED` сервер → клиент  
`body`: `{ "room", "nick", "peers", "history": [ CIPHER-кадры ] }`

`PEERS` сервер → комната  
`body`: `{ "room", "count" }`

`LEAVE` клиент → сервер (или закрытие сокета)

### Сообщения

`CIPHER` клиент → сервер → все в комнате  
`body`: `{ "room", "nick", "iv": "b64", "data": "b64" }`

### Рация (PTT, как у Zello)

Канал комнаты один: кто первый нажал `PTT_START`, тот говорит. Остальным `ERROR / PTT_BUSY`.

`PTT_START` → `PTT_CHUNK`* → `PTT_END`

`PTT_CHUNK.body`: `{ room, nick, seq, mime, iv, data }`  
`data` — AES-GCM кусок Opus/WebM (~400 мс). Сервер не хранит эфир, только ретранслирует. Лимит кадра 96 КБ.


`iv` — 12 байт AES-GCM. `data` — шифротекст + тег GCM.  
Сервер не расшифровывает, только ретранслирует и кладёт в кольцо на 50 штук.

`ACK` сервер → отправителю  
`body`: `{ "of": "<id CIPHER>" }`

### Служебные

`PING` / `PONG` — `body` пустой или `{ "n": 1 }`  
`ERROR` — `body`: `{ "code": "BAD_COMMIT", "of": "<id>" }`

Коды: `NO_HELLO`, `BAD_FRAME`, `BAD_COMMIT`, `TOO_LARGE`, `NOT_IN_ROOM`, `UNKNOWN_TYPE`.

## Что это даёт и чего нет

Даёт: свой формат, версию, рукопожатие, вход по commitment без пароля на сервере, шифротекст как единственное содержимое чата.

Нет: бинарного фрейминга как у MTProto, Perfect Forward Secrecy, отдельных ключей на устройство, подписи кадров, антицензурного обфусцирования. Это протокол приложения, не замена TLS: снаружи всё равно WSS.
